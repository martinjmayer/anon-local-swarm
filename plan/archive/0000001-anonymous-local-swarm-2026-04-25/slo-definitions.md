# SLO Definitions - Autonomous Local Swarm

## Context

This is a local, single-operator tool with no external users, no uptime commitment, and no error budget in the traditional sense. SLOs here define internal quality targets measurable via obs.db.

---

## SLIs / SLOs

| ID | Indicator (SLI) | Objective (SLO) | Measurement |
|----|----------------|----------------|-------------|
| SLO-001 | Time from task unblocked to task dispatched | ≤ 2 seconds (p100) | obs.db: delta between blocked→pending and pending→active timestamps |
| SLO-002 | Self-correction success rate | ≥ 60% of failed GO_CODE tasks succeed within 5 retries | obs.db: completed self-correction tasks / total self-correction chains |
| SLO-003 | MCP tool availability | ≥ 80% of MCP tool calls succeed per run | obs.db: mcp_tool_success / (mcp_tool_success + mcp_tool_failure) per project |
| SLO-004 | Context compression latency | SUMMARY task completes within 60 seconds | obs.db: SUMMARY task active→completed delta |
| SLO-005 | Output deposit completeness | 100% of terminal-state projects have artifacts deposited | obs.db: output_deposited events vs terminal_state events |

## Error Budget

Not applicable — local tool, no production traffic. SLOs are aspirational quality targets. Violations are logged in obs.db for operator review, not paged.
