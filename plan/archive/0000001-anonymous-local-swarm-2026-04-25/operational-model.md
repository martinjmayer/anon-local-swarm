## Startup Sequence

1. Start Ollama (`ollama serve`)
2. Verify required models are pulled: `ollama list` — must include phi-4:mini, llama3.1:8b, qwen2.5-coder:7b, smollm3:135m
3. Set environment variables: `BRAVE_API_KEY`, `GITHUB_TOKEN`, `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`
4. Start MCP server processes (mcp-reddit and any others that require explicit launch)
5. Start orchestrator: `./als --config config.yaml`
6. Insert seed task into swarm.db to begin a project run

## Shutdown

- SIGTERM or SIGINT causes the orchestrator to: complete the current active task (or cancel if it exceeds 30s), flush obs.db writes, close swarm.db, exit cleanly
- Active tasks interrupted at shutdown are reset to `pending` on next startup

## Runbook Triggers

| Condition | Signal | Operator Action |
|---|---|---|
| Orchestrator exits at startup | stderr: "model not found" | `ollama pull {model-name}` then restart |
| Orchestrator exits at startup | stderr: "Ollama unreachable" | `ollama serve` then restart |
| All tasks pruned, no output | obs.db: prune events with low scores | Review prune-report.md; re-seed with refined prompt |
| Self-correction loop halted | obs.db: failed events | Inspect stderr chain in obs.db; fix prompt or code; re-seed |
| MCP tool repeatedly failing | obs.db: mcp_tool_failure events | Check credentials; restart MCP server process; verify API key validity |
| obs.db growing very large | File size > 1GB | Query and archive old events; no automated rotation in v1 |

## Recovery Procedures

**Stalled active task:** If a task has been `active` for > 30 minutes with no obs.db events, the Ollama process may have hung. Kill the orchestrator, reset the task to `pending` in swarm.db (`UPDATE tasks SET status = 'pending' WHERE id = '{id}'`), restart.

**Corrupt swarm.db:** Restore from backup. swarm.db should be backed up before each project run. No automated backup in v1 — operator responsibility.

**mcp-reddit auth failure:** Revoke and re-issue Reddit app credentials. Update environment variables. Restart mcp-reddit process.

## No On-Call

This is a local, single-operator tool. There is no on-call expectation, SLA, or alerting infrastructure. The operator monitors stdout and queries obs.db as needed.
